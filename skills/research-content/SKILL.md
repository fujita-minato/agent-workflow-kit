# Research content

1. Read current topics, rejected ideas and prior reference notes. Identify the audience question or the cut you need to learn.
2. Find an installed skill for the source type or discovery task. Read its scope before use. Personally inspect an original and a traceable first-party source. If a signed-in browser is needed, verify the project's configured profile and account for this task. Stop on a mismatch, blocked access or an explicit rate limit.
3. Give a worker query groups, primary source types, page budget, boundaries and a result format. Deduplicate by canonical material, not only the displayed title. Preserve the date, author, original URL, quotation or timestamp, and uncertainties.
4. Produce a few actionable cards. A topic card states the audience's question, what the evidence supports and under what conditions. An editing card states the visible before, action and result, includes a real timestamp and frame reference, and describes a test on one shot. State what you could not verify.

If a worker cannot use the approved browser under its current permissions, keep browser collection with the authorized lead. Give the worker the resulting records for comparison and deduplication, and report which search batches could not run.

Read sites and tools within the project's authorization. Keep raw or private source material in the team's workspace, and do not install new skills as part of research without authorization.
